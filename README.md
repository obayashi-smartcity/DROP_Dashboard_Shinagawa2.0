# DROP_Dashboard_Shinagawa2.0 — 投稿づくりチャット DROP. Coach（品川 V2）

CULTURE SNACK（コクヨ × 大林組）で、参加者が DROP に投稿する文を、チャットで一緒につくるツールと、その記録を分析する画面です。
V1（DROP_Dashboard_Shinagawa1.0）とは GAS・プロンプト・記録シートをすべて分けています（V1 には一切影響しません）。

## チャットの流れ（v3.1）

問いの考え方：**ひとこと（自由に書く問い）で何について投稿するかを決め、あとは選択肢で答える問い（タップ中心）**。
最低限（何・どう・なぜ・誰と）がそろったら投稿文をつくれます。それより先は任意で、本人が答えるかどうかを選びます（誘導しない）。

1. ログイン（この端末で 1 回だけ。答えの使い道を一言添える）
2. 写真をえらぶ（写真なしでも可）
3. **ひとこと**（必須・自由に書く）… 投稿文のもと。キーボードのマイクで話して入力も可
   - 画面がひとことを読み取り（気持ち・人・話題）、返事をしてから次へ。裏で AI のヒント（話題・写真から見える候補）
4. **気持ち**（ひとことに書かれた気持ちは先に選んでおく。近い順に選ぶ）
5. **どこが**（いちばん大事な気持ちについて、運営が設定した候補から近い順に選ぶ。例：かわいい → 商品／ショッパー（袋）／お店の飾りつけ／お店の人。1・0.75・0.5・0.25 の重みで記録）
6. **だれと**（「どんな人？」は会社・部署・立場などで、と答え方の手がかりつき）
7. 「これで投稿文に必要なことがそろいました！」→「投稿文をつくる」か「もう1つ答える（任意）」を本人が選ぶ
8. （任意）**このあと**、どうしたいか
9. あなたについて（端末ごとに 1 回）
10. 投稿文：「AI が整えた文／自分の言葉の文」を切り替え・直せる（AI の手直しは最低限）。ハッシュタグは付けない設定から始まる → コピーして DROP へ
11. コピーすると「今日の投稿スタンプ」（5 つで 1 枚）と、いちばん大きなボタン「次の写真で、もう1本つくる」。2 本目からはあいさつも短く

- 上部の円で「最低限の問い」の進み具合（例 2/4）。「あなたの投稿」バーで、答えるたびに投稿が育つのが見える。押すと「入っているもの」と「ほかの人の例（見本）」
- 見本はひとことを書いたあとにだけ開ける（最初の言葉が見本に引きずられないように）
- ひとことを書いたあとは、いつでも「ここまでで投稿文をつくる」
- メニュー：文字を大きく／ほかの人の例／このチャットについて／最初からやり直す／「あなたについて」を答え直す／ログアウト
- URL に `?staff=1` を付けると、分析用の記録（ノード・ソフト分類・JSON）と、その端末の記録の CSV 保存が出る（運営の確認用）

## チャットの設定（選択肢と重み）を変える ― 非エンジニア向け

1. `drop_coach_dashboard.html` を開き、上の「チャットの設定」を押す
2. 管理者パスワードでログイン（見るだけ・「ためしに計算」はログインなしでも使える）
3. タブごとに変える：気持ちと「どこが」／「どこが」の共通の候補／だれと／このあと／選んだ順の重み／あなたについて
   - 表示名・表示する／しない・並び順・追加（初期値の選択肢は削除できず、表示を外す）
   - KPI の重み（①挑戦・②属性横断・③心理的安全性・街への愛着）は 0〜1。迷ったら 0・0.3・0.5・1 の 4 段階で十分
   - 気持ちの向き（◎〜×）、気持ちごとの「どこが」の候補と問い文（`{話題}` はひとことの話題に置きかわる）
4. 「ためしに計算」で答えを押して、結果と計算の中身を確認
5. メモを書いて「保存する」→ 全員のチャットに反映（開きなおしたとき・次の投稿から。最大 5 分ほど）。答えている途中の人には影響しない
- 保存のたびに settings シートに履歴が残る。「保存の履歴」から前の版を読み込んでもどせる。ほかの人が先に保存していたら知らせる
- 分析画面の「KPI・気持ちの向きの重み」で「いまの設定で計算し直す」を選ぶと、過去の記録もいまの重みで見られる（記録には何を何番目に選んだかが残っているため）
- 重みのしくみの説明は、設定画面の「はじめての方へ」にもあります

## 設定（GAS・画面）

### GAS のスクリプトプロパティ

**DROP_COACH_GPT（仕上げ用）**

| キー | 値 |
|---|---|
| `APP_PASSWORD` | 参加者に配るパスワード（LOG と同じ値） |
| `AZURE_API_KEY_LUNA` | Azure OpenAI の API キー（**リポジトリには絶対に書かない**） |
| `PROMPT_URL_CHAT` | `https://raw.githubusercontent.com/obayashi-smartcity/DROP_Dashboard_Shinagawa2.0/main/prompt/drop_coach_chat.md` |
| 任意 | `DAILY_LIMIT`（400）・`PROMPT_CACHE_SEC`（300）・`PROMPT_URL_HINT`（未設定なら同じフォルダの drop_coach_hint.md）ほか。GAS の先頭のコメント参照 |

**DROP_COACH_LOG（記録用）**

| キー | 値 |
|---|---|
| `APP_PASSWORD` | 参加者に配るパスワード（GPT と同じ値） |
| `ADMIN_PASSWORD` | 分析画面・チャットの設定用の管理者パスワード（**APP_PASSWORD とは別の値**） |
| `LOG_SHEET_ID` | V2 のスプレッドシート LOG_DROP_COACH の ID（**V1 のシートの ID にしない**） |
| `LOG_SHEET_NAME` | `chat_v3` |
| 任意 | `SETTINGS_SHEET_NAME`（settings）ほか |

### 画面の設定（`drop_coach_chat.html` の `CONFIG`。エンジニア向け）

| キー | 既定 | 内容 |
|---|---|---|
| `GAS_URL`・`LOG_URL` | 設定済み | 2 つの GAS の /exec URL |
| `ASK_SCORE` | false | 体験の点数（10 点満点）を聞く。既定は聞かず、選んだ気持ちから「気持ちの向き」を計算 |
| `HASHTAGS_ON` | false | ハッシュタグを最初から付ける |
| `HINT_ON` | true | ひとことの直後に裏で AI ヒントを呼ぶ |
| `SHUFFLE` | true | 選択肢の並びをシャッフル（並びは記録する） |
| `DROP_URL` | 空 | 入れるとコピー後に「DROP を開く」ボタンを出す |
| `ALLOW_NO_LOGIN` | false | true で「ログインせずに使う（AI・記録なし）」を出す（全員分を記録する方針のため false） |

選択肢の言葉・重みは `CONFIG` ではなく「チャットの設定」で変えます。

## 更新の手順（v3.0 → v3.1）

1. このフォルダを GitHub（main）に push する（**`drop_coach_with_sample.html` は削除**。チャットは `drop_coach_chat.html` に名前を変えた）
2. **GitHub Pages を有効にする**（まだなら）：リポジトリの Settings → Pages → Source「Deploy from a branch」→ Branch「main」「/(root)」→ Save。数分後に
   `https://obayashi-smartcity.github.io/DROP_Dashboard_Shinagawa2.0/drop_coach_chat.html` で開ける（V1 のリポジトリを複製しても Pages の設定は引き継がれない）
3. **DROP_COACH_GPT**：`gas/DROP_COACH_GPT.gs` を貼り替え → `checkSetup` → `testHint` → `testChat` → デプロイを管理 → 編集 → 新しいバージョン（URL は変わらない）
4. **DROP_COACH_LOG**：`gas/DROP_COACH_LOG.gs`（v8）を貼り替え → スクリプトプロパティ（`LOG_SHEET_NAME`＝`chat_v3`・`ADMIN_PASSWORD`）を確認 → `setupTest` を実行（chat_v3 シートの見出しが 59 列に、settings シートができる）→ 新しいバージョン
5. 確認：`LOG_URL?diag=1`（`sheet_ok`・`admin_password_set` が true、`settings_version`）→ チャットで 1 回投稿 → 分析画面に管理者パスワードでログインして 1 件出ること → 「チャットの設定」で開けること

v2 の記録（`log` シート）は消さずに残ります。v3 からは `chat_v3` シートに書きます。

## 見本投稿を変えるとき

`json/sample_drop.json` と `json/sample_img/` を差し替えます。HTML の中の `<script id="sampleFallback">` には同じ JSON の控えが入っています（`file://` で直接開いたときだけ使う）。GitHub Pages では json を読むので、控えを更新しなくても動きます。
同じように `<script id="defaultSettings">` には `json/coach_settings_default.json` の控えが入っています（初期値を変えたいときは、ふつうは「チャットの設定」で保存すれば十分です）。

## 記録（chat_v3 シートの列）

1 回のチャットで「投稿文ができた（完了）」「コピーした（コピー）」「途中でやめた（途中離脱）」「やり直した（やり直し）」のときに 1 行ずつ書きます。同じセッション ID の行が複数あるときは、分析画面がいちばん新しい行を使います。

| まとまり | 列 |
|---|---|
| いつ・だれ | タイムスタンプ／Name／セッションID／終了／開始／所要秒／回答数／最後の問い／写真 |
| ひとこと | 最初のひとこと／ひとことから読み取れたもの（画面の辞書）／話題（AI ヒント → 画面の読み取り） |
| 答え | だれと／どんな人／どこが（近い順）／どこがの選び方（選択肢・AI候補・自分で）／気持ち（選んだ順）／気持ちの向き（-1〜1）／このあと／属性／体験の点数（ASK_SCORE のときだけ） |
| 分析用 | ノード（共起用：`人:…`・`コンテンツ:…`・`空間:…`・`感情:…`・`意向:…`）／ソフト①挑戦・②属性横断・③心理的安全性・愛着（答えから計算・合計 1） |
| 投稿文 | 組み立て文面（自分の言葉の文）／AI文面／最終文面／採用（AI・自分の言葉）／手で編集／コーチ関与（ひとことのみ・選択あり・AI仕上げ）／ハッシュタグ |
| AI の読み取り | AI分類／AIソフト／AI感情の向き／AI行動／AIコンテンツ／AI空間／AI 5W1H／AI評価／AIひとこと／写真と本文／AI注意 |
| 使われ方 | ヒント状態（秒）／ほかの人の例を見た（回数・どこで）／投稿イメージを開いた／表示順（シャッフルの結果）／問いごとの秒 |
| 版 | AIモデル／プロンプト版／AI秒／アプリ版／記録JSON（画面が送った記録そのもの） |
| v8 で追加 | どこがの気持ち（「どこが」の候補を選んだ気持ち）／どこがの重み（例「商品 1 / ショッパー（袋） 0.75」）／設定版／任意の問い（答えた・投稿文へ）／この端末で何本目 |

## 分析画面（`drop_coach_dashboard.html`）

- 読み込み：①記録用 GAS から（管理者パスワード）②スプレッドシートの CSV ③デモデータ（架空・見え方の確認用）。上の「← データの読み込み方を選ぶ」でいつでも選びなおせる（読み込んだデータの分析にもどることもできる）
- 見られるもの：全体の数字（2 本以上コピーした人・任意の問いにも答えた人を含む）／到達・問いごとの回答率・時間・途中でやめた場所・時間帯／気持ちのランキングと向き（AI の読み取りとの一致）／**気持ちの中身**（例：「かわいい」は何に対してか。近い順の重みの合計）／だれと・どこが・このあと・話題・材料の数・属性／共起ネットワーク／KPI ソフト分類（本人の答え vs AI）と一致率／コーチの関与・「ほかの人の例」を見たかでの比較／投稿一覧（検索・詳細）
- 共起ネットワーク：何も選んでいないときは、いちばん多い組み合わせをマゼンタで表示。丸を押すと、そのノードとよくいっしょに出るものと「出やすさ」。同じ丸をもう一度押す・図の何もないところを押す・Esc で解除
- 絞り込み（日付・写真・属性・関与・状態）と「重み（記録したとき／いまの設定）」はすべての図と表に効く。絞り込んだ結果と、共起の線の一覧は CSV で保存できる
- 色の見方：マゼンタ＝その図で注目してほしいところ／グレー＝その他・比較相手／青・淡青・黄・赤（◎○△×）＝気持ちの向き／青緑・オレンジ（↑↓）＝多い・少ない／紫の濃淡＝段階
- 名前とひとことが表示されるので、共有・印刷に注意。パスワードは保存せず、ログインはブラウザのタブを閉じるまで

## 設計の考え方（2026/11/13 改良会議と定例後のご意見）

1. 聞いてから聞く：ひとことを受けて返し、ひとことに書かれた気持ち・人は先に選んでおく。問いの言い方もひとことの話題を使う
2. 自由に書く問いは「ひとこと」だけ（何について投稿するかを決める）。あとは選択肢中心で、打ち込む負担を減らす。どの問いにも「ほかにあれば」の自由記述と「とばす」がある
3. 最低限（何・どう・なぜ・誰と）がそろえば投稿文へ。その先は任意で、本人が選ぶ（誘導尋問にしない）。AI の手直しも最低限（本人の言葉を残し、盛らない）
4. 選択肢は偏らないように：中立・ネガティブの選択肢、表示順のシャッフル（記録する）、見本はひとことのあとだけ。ポジティブな投稿と決めつけない（ひとことにネガティブな手がかりがあれば「いいですね」と返さない／投稿文を前向きに書き換えない／「このあと」に「運営に伝えたいことがある」）
5. 投稿がどう育つかを常に見せる（深掘りのゴールが見える）。ラベルは出さない
6. AI は 2 回・待たせない（ひとことの直後に裏でヒント、最後に投稿文）
7. 本人が選べる：AI の文／自分の言葉の文。ハッシュタグは本人が決める
8. もう 1 本つくりたくなる：投稿スタンプ、「次の写真で、もう1本つくる」、2 本目からは短いあいさつ（ログイン・属性は聞かない）
9. お年寄りにやさしく：大きな文字とボタン、「#」なし、「次へ」「とばす」はボタン、文字を大きくするメニュー、話して入力の案内、小さい画面でも問いが隠れない
10. 運営が決めることは運営が変えられる：選択肢と重みは「チャットの設定」で。変えても過去の記録を計算し直せる
11. 効果測定の注意：コーチの関与（ひとことのみ／選択あり／AI仕上げ）、見本を見たか、選択肢の表示順、設定版を記録し、分けて比べられるようにする
